# Existing e2e, base vs HEAD (change plan, optional)

Used only for an app whose change-plan e2e result is `skipped: no e2e in plan` and that has a Playwright harness. Offer it; do not run it unasked, because it runs the app's suite twice. In a repo where many existing e2e tests already fail, this is what shows the change broke none of them.

1. Ask the user which spec files or folder to run (default: the app's whole e2e folder minus `excludePaths`).
2. Create a temporary worktree at `plan.baseCommit` (`git worktree add --detach <scratch dir> {baseCommit}`), install dependencies there the way the repo's own setup does, and, under the same feature lock as the change-plan e2e run, run the same command in both trees, one after the other (never in parallel — both harnesses own the same dev-server port). Many suites write captures (screenshots, artifacts) into tracked files, so right before the HEAD run save `git status --porcelain=v1 -z --no-renames --untracked-files=all` of the checkout to a scratch file, and right after it — before anything below writes a record — save a second one the same way. With `--no-renames` each NUL-terminated record is `XY` + space + one path; `??` marks untracked. Restore each path that is in the second status, absent from the first (it was clean before), and changed in the worktree only (`X` is a space: ` M`, ` D`) by passing those paths NUL-separated to `git restore --worktree --pathspec-from-file=- --pathspec-file-nul` (never split on spaces), and list (do not delete) untracked paths that are new. A path whose index the run changed (`X` not a space, e.g. `A`, `D`, `M`) is not touched, and neither is a path the user had already changed before the run that the run changed again: name both. Report what was restored.
3. Compare per test, not by totals: list tests that pass on base and fail on HEAD (regressions), and those that fail on base and pass on HEAD. Equal totals with different failing tests is not "no change".
4. Record under `implementation.e2e.apps.{app}.baseComparison` `{ baseCommit, command, base: {passed, failed, skipped}, head: {...}, regressions: [names], fixed: [names] }`. The app's e2e result stays `skipped: no e2e in plan` — a comparison with no regressions is evidence for the PR body, not a pass. Any regression → remove the worktree (item 5), release the lock, report it and stop for the user.
5. Remove the temporary worktree (`git worktree remove --force` — it is scratch, and the base run may have dirtied it) before every stop, including a failed run, and, when a HEAD run stopped before item 2's restore, do that restore first. Records written in item 4 are never restored.
